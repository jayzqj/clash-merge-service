# 0006 linux.do 分组的成员规则与纯净度阈值

状态：已接受

## 背景

ADR 0001 / 0005 确定服务端预选只看“本轮连通、纯净度达标”。需要确定纯净度标准，以及与现有 `🎯 纯净优选`（`app/groups.py`，硬编码 ≤15、排除 http 类型）的关系。

纯净度是出口 IP 的 fraudScore。它和 Cloudflare 内部的 IP 信誉判断相关，但不完全等同；目前没有更直接、可批量测的“会不会被 Cloudflare 验证”的指标。

## 决策

成员条件：

- 已进入本轮输出的节点（已通过连通性及其他过滤）；
- 非 http 类型（与 `🎯 纯净优选` 一致）；
- 有纯净度分数（本轮或沿用的历史分数），且分数 ≤ 阈值，包含等于；没有分数的节点不收。

阈值单独配置：

- 新配置项（暂定名 `linuxdo_purity_threshold`），管理页可改；
- 默认 15，取值 0–100，支持小数；
- 完整执行和“重新应用规则”都按当前配置值计算成员。重新应用规则从节点名解析分数（`names.parse_score`），所以改阈值后点“重新应用规则”即可生效，不必等下一轮完整检测。

## 备选方案

- **与 `🎯 纯净优选` 成员完全相同**：直接复用 `low_purity_members`，实现最简单，但无法单独调严或调松。用户选择单独配置。
- **跟随全局 `purity_threshold`（“纯净度 预留%”）**：该值当前只在开启纯净度过滤时使用，兼做两件事含义会混。放弃。
- **默认 5 / 默认 100**：5 可能导致成员过少甚至为空；100 等于上线时不按纯净度筛。放弃。

## 后果

- 正面：上线时成员与 `🎯 纯净优选` 相同，行为可预期；之后可按验证频率单独调整。
- 负面：需要改配置校验（`app/config.py`）、接口字段（`app/web.py`）、管理页和测试；`low_purity_members` 需要改为接受阈值参数。
- 跟进：成员为空时的处理另行决策。
