# 0012 linux.do 分组使用 mihomo 默认测速超时

状态：已接受。取代 ADR 0004 中 `timeout: 2000` 一项，ADR 0004 的间隔 300 秒、容差 200ms 仍有效。

## 背景

ADR 0004 定了 2000ms 超时。实现时发现 `app/converter.py` 的 `_classify_field` 会解析 `interval,timeout,tolerance`，但丢弃中间的超时值，`build_proxy_groups` 也不输出 `timeout`，Clash Verge 使用 mihomo 默认的 5000ms。

如果让转换器输出超时，现有地区分组写的 `300,1000,100` 中的 1000ms 也会同时生效。本机实测 `cp.cloudflare.com` 经美国出口耗时 941–1176ms，美国等远端分组可能被判为全部不可用。

## 决策

- 转换器不改；
- ini 中内层分组写 `300,,200`（间隔 300 秒，超时留空，容差 200ms），实际超时为 mihomo 默认 5000ms。

## 备选方案

- **转换器输出超时，对所有分组生效**：符合 subconverter 语义，但会改变现有分组行为，需要用户先调大现有分组的超时。放弃。
- **只对名字含 LinuxDo 的分组输出超时**：同一种写法在不同分组里含义不同，容易搞混。放弃。

## 后果

- 正面：现有分组行为不变，无代码改动。
- 负面：超过 2 秒的节点也算“可用”；不过选哪个节点仍按延迟和 200ms 容差决定，只有所有成员都很慢时才会选到这类节点。
- 跟进：以后如果需要全局支持超时，需新建 ADR，并同时检查现有分组的超时值。
