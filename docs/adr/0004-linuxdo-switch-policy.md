# 0004 linux.do 分组的自动切换策略

状态：已接受。`timeout: 2000` 一项 Superseded by 0012（改用 mihomo 默认 5000ms）。

## 背景

`cf_clearance` 等验证结果和出口 IP 相关，换出口后容易被要求重新验证。现有地区分组的 url-test 参数为 `300,1000,100`（间隔 300 秒、超时 1000ms、容差 100ms）。本机实测几分钟内 linux.do 的出口就从日本（188.253.118.70）变成了新加坡（168.144.255.28）。

另一方面，ADR 0001 要求由客户端按用户网络挑选快的节点，不能完全不切换。

## 决策

linux.do 分组使用 `url-test`：

- `interval: 300`（每 300 秒测一次）；
- `timeout: 2000`（毫秒）；
- `tolerance: 200`：新节点比当前节点快 200ms 以上才切换；当前节点测速失败时立即切换。

## 备选方案

- **fallback**：按服务端排好的顺序用第一个能通的节点，只在故障时切换。出口最稳，但客户端不再挑最快的，等于放弃 ADR 0001 的客户端测速。放弃。
- **沿用 `300,1000,100`**：与地区分组一致，但切换最频繁，重复验证问题继续存在。放弃。
- **select**：永不自动切换，节点故障需手动更换。放弃。

## 后果

- 正面：延迟差距小于 200ms 时保持当前出口，减少换 IP 导致的重复验证；节点故障仍会自动恢复。
- 负面：可能停留在比最优节点慢不到 200ms 的节点上。超时放宽到 2000ms，是因为本机首次请求曾测到约 3.4 秒；超过 2 秒的节点视为不可用。
- 跟进：上线后观察验证频率；如果仍频繁，再考虑加大容差或改用 fallback（需新建 ADR）。
