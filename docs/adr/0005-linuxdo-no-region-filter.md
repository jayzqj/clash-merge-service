# 0005 linux.do 分组不按出口地区预选

状态：已接受。修正 ADR 0001 中“出口在离 Cloudflare 近的地区”这一预选条件，ADR 0001 其余内容仍有效。

## 背景

ADR 0001 的服务端预选包含三个条件：本轮连通、纯净度达标、出口在日本 / 香港 / 新加坡 / 韩国等近 Cloudflare 地区。

ADR 0003 确定客户端测速地址为 `https://linux.do/cdn-cgi/trace`，测的正是“用户网络 → 节点 → linux.do 所在 Cloudflare 机房”的延迟。出口地区远近已经体现在这个延迟里，再按地区筛选是重复判断。

## 决策

服务端预选只看两项：本轮连通、纯净度达标。不按出口地区筛选，地区远近交给客户端测速。

## 备选方案

- **按实测出口国家筛（JP/HK/SG/KR）**：比看节点名准确，但“重新应用规则”时没有实测数据，只能退回看节点名里的国旗，两条路径的结果可能不同。放弃。
- **按节点名里的国旗筛**：两条路径一致，但名字写香港、实际从美国出口的节点会被误收。放弃。

## 后果

- 正面：规则更少；完整执行和重新应用规则两条路径不会因地区判断不同而出现分歧；近端节点全部故障时还能自动退到远端节点。
- 负面：分组成员更多，Clash Verge 每 300 秒测速的请求数随之增加。
- 跟进：如果成员过多导致测速负担明显，再考虑限制数量（需新建 ADR）。
